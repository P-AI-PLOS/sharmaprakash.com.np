# Agent recipes — "Before you touch X, read Y"

AI explainers: Markdown can contain `<ai-diagram data-diagram="prefix">`
with a static SVG image and explanatory paragraph as its children. The
Running AI Yourself post layout loads `AiDiagrams.astro` to enhance these
elements; without JavaScript the fallback remains readable. Diagram state
and SVG rendering live in `src/data/ai-diagrams.mjs`. After changing that
module, run `node scripts/images/render-ai-diagrams.mjs` to refresh the
committed SVG fallbacks, and `node --test scripts/tests/ai-diagrams.test.mjs`.

AI glossary: definitions live once in `src/data/ai-glossary.mjs` and render
at `/ai/glossary/`. Link a term as `[inference server](/ai/glossary/#inference-server)`.
AI-directory posts show a definition on hover or focus; the ordinary link
works on touch and without JavaScript. Keep fragment IDs stable.

| Add a blog post | `src/content/posts/` using filename pattern `YYYY-MM-DD-slug.md` only; do not create undated post filenames. The `date` frontmatter must match the filename date. Schema lives in `src/content.config.ts`. Required frontmatter: `title`, `date`, **`directory: <category>`** (without it, `src/utils/posts.ts:121` routes the post to `/<slug>/` instead of `/<category>/<slug>/` and breaks under the expected URL — set `directory` alongside `category`, not in place of it). Common optional: `excerpt`, `categories`, `tags`, `cover`, `thumb`, `series` + `seriesOrder`. Set `draft: true` to hide a post from all listings, feeds, and the sitemap (filter lives in `src/utils/posts.ts`). |
| Create a featured image — **AI-category post** | Run `pnpm blog-image:ai src/content/posts/<post>.md`. Writes `public/images/blog/ai/<slug>.png`, 21:9 at 1915×821, one image per post. This style is a title card **with text baked in**: white card on the left holding an amber chip, headline and sub-line, plus a bespoke schematic on the right. Card copy is derived from frontmatter, but the schematic is per-post and can't be — add an entry to the `HEADERS` registry in [`scripts/images/render-ai-header.mjs`](../../scripts/images/render-ai-header.mjs), which pins the line breaks, type sizes, pill and a `diagram` builder. Same per-slug registry pattern as `getVisualLines()` in `render-blog-header.mjs`. A registered post re-renders byte-identically, so regenerating never silently redesigns a published image; an unregistered post gets auto-layout, an empty right half, and a warning saying so. |
| Create a featured image — **series post** | Text-free editorial illustration (photoreal/3D — no embedded text, no logos, no watermarks), generated with Codex image generation. Save the 21:9 hero as `cover.png` and the 16:9 card crop as `thumb.png` under `public/images/blog/<series>/<slug>/`. A house-style prompt worth copying sits in the `# Image prompt` HTML comment at the foot of `src/content/posts/2026-03-30-monorepo-tasks-and-ci.md`. **For batches of more than ~6 images, fan out across 2–3 parallel Codex workspaces** (`cmux new-workspace --command "codex"`); split posts into roughly equal batches (~4–5 images each), tell each instance to write files only — no commit — then batch-commit at the end to avoid concurrent-commit races. |
| Wire a featured image into a post | Set `use_featured_image: true` **and** at least one of `cover` / `thumb`. `postCoverImage()` and `postThumbnail()` (`src/utils/posts.ts`) each check the flag first, then prefer their own field and fall back to the other one, so a single path in both fields is fine — that's the AI-category case. Forget the flag and they silently return `categoryFallbackImage()` instead: the post still renders, just with a generic category image, which is the failure mode to watch for. Post heroes and OG tags read `cover`; cards and listings read `thumb`. Note the older `pnpm blog-image:render` renders a different, terminal-lines card into `public/images/blog/generated/{covers,thumbs}/<slug>.png`; it backfills pre-2020 posts and isn't the style to reach for on new work. |
